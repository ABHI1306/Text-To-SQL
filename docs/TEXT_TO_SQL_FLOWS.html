Text-to-SQL Flows
Study sheet

Two flows through the Text-to-SQL platform

Case 1 is what a DBA does once to connect a database. Case 2 is what happens each time a user asks a question. Case 2 only works because Case 1 left four things behind: a project, a live model, vectors in Qdrant and row policies.

Case 1

A DBA connects a database

Seven steps, one per wizard screen. Every step goes through the API. The orange arrows are the steps that refuse unsafe input.

normal callsafety check
After stepWhat now existsWhere
1A signed JWT proving who the DBA isBrowser
3A project with Fernet-encrypted credentials. The password is never stored in plain text.metadata-db
5A draft model: tables, columns, relationships, plain-English descriptionsIn the wizard
6MDL revision N, saved but not live. Every table and column was checked against the real catalog.metadata-db
7One vector per model, column and relationship, tagged with project and version. Revision N is now active.Qdrant, metadata-db

Before users can ask anything, the DBA also creates roles and users, grants project access, adds row policies such as region = {{ user.region }}, and sets user attributes such as region = West.

WITH m_orders AS (
  SELECT ... FROM public.tbl_orders
  WHERE region = %(p_region)s)

-- p_region = 'West'

Same code for Ravi gives 'East'. A user with no region gets FALSE, so zero rows.
